# Руководство для AI-агентов: Управление Docker-инфраструктурой (cu-roadmap)

Данный документ определяет стандарты и процедуры управления контейнеризированным окружением проекта. Агенты должны придерживаться этого руководства для обеспечения стабильности среды разработки и развертывания.

## 1. Подготовка окружения
Перед выполнением любых команд необходимо убедиться в выполнении следующих условий:
- **Docker Engine**: Сервис Docker должен быть запущен на хост-системе.
- **Файл конфигурации**: В корневой директории должен присутствовать файл `.env`. При его отсутствии необходимо инициализировать его на основе `.env.example`.
- **Рабочая директория**: Все команды выполняются строго из корня проекта `cu-roadmap`.

## 2. Основные сценарии развертывания
Для инициализации и запуска полного стека сервисов (Backend, Frontend, Nginx, Database) используется стандартный поток команд.

### 2.1 Быстрый запуск (Docker Compose)
Основной метод запуска всей системы в фоновом режиме:
```powershell
docker-compose up -d --build
```

### 2.2 Использование вспомогательных скриптов
Для кросс-платформенной совместимости рекомендуется использовать системные скрипты:
- **Windows (PowerShell)**: `.\scripts\manage_docker.ps1 -Action up`
- **Linux/macOS (Bash)**: `./scripts/manage_docker.sh up`
- **Универсальный метод (Make)**: `make up`

## 3. Протоколы обновления компонентов
При внесении изменений в исходный код (backend или frontend) требуется пересборка соответствующих образов.

### 3.1 Обновление Frontend
Для пересборки и перезапуска только фронтенд-сервиса без остановки всей системы:
```powershell
docker-compose up -d --no-deps --build frontend
```
**Альтернатива**: `.\scripts\manage_docker.ps1 -Action rebuild-front`

### 3.2 Обновление Backend
Для пересборки и перезапуска только бэкенд-сервиса:
```powershell
docker-compose up -d --no-deps --build backend
```
**Альтернатива**: `.\scripts\manage_docker.ps1 -Action rebuild-back`

## 4. Мониторинг и обслуживание
### 4.1 Просмотр логов
Для отладки и мониторинга состояния сервисов в реальном времени:
```powershell
docker-compose logs -f
```

### 4.2 Остановка системы
Для полной остановки и удаления контейнеров, сетей и томов:
```powershell
docker-compose down
```

## 5. Архитектурная справка (Docker Stack)
- **Nginx (Entry Point)**: Проксирует запросы, доступен по адресу `localhost:9679`.
- **Backend (API)**: Python/FastAPI приложение (контекст `./backend`).
- **Frontend (UI)**: Vite/React приложение (контекст `./frontend`).
- **Database (PostgreSQL)**: Хранилище данных. По умолчанию может использовать `USE_MEMORY_STORE: "true"` для быстрой разработки.
