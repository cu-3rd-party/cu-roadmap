# Course Restrictions - Quick Start Guide

## Что это такое

Ограничения (restrictions) позволяют настроить минимальное и максимальное количество курсов определённой категории, которое студент должен взять в каждом семестре для конкретной специализации.

## Примеры использования

### Пример 1: Требовать хотя бы один STEM-курс каждый семестр

Для каждой специализации создайте 8 ограничений (по одному на семестр):

```json
{
  "semester": 1,
  "category": "stem",
  "min_courses": 1,
  "max_courses": 999
}
```

Повторите для семестров 2-8.

### Пример 2: Ограничить Soft Skills одним курсом в семестр

```json
{
  "semester": 2,
  "category": "soft",
  "min_courses": 0,
  "max_courses": 1
}
```

### Пример 3: Требовать ровно 2 AI курса в 5-м семестре

```json
{
  "semester": 5,
  "category": "ai",
  "min_courses": 2,
  "max_courses": 2
}
```

## Как настроить в админке

1. Откройте админ-панель (`/admin`)
2. Перейдите на вкладку **"Специализации"**
3. Выберите мейджор из dropdown
4. Нажмите ⚙️ рядом с нужной специализацией
5. Нажмите **"Добавить ограничение"**
6. Заполните форму:
   - **Семестр**: 1-8
   - **Категория курсов**: fundamentals, ai, stem, soft, business, tech, swe, design
   - **Минимум курсов**: минимальное количество (0 или больше)
   - **Максимум курсов**: максимальное количество (до 20)
   - **Описание**: заметка для администраторов (опционально)
7. Сохраните

## Категории курсов

- `fundamentals` - Основы
- `ai` - Искусственный интеллект
- `stem` - STEM (технические курсы)
- `soft` - Soft skills
- `business` - Бизнес
- `tech` - Технологии
- `swe` - Software Engineering
- `design` - Дизайн

## Как это работает

### Валидация семестра

Когда студент выбирает курсы на семестр, система проверяет:

1. Считает количество курсов каждой категории
2. Сравнивает с ограничениями для этого семестра
3. Возвращает ошибки, если мин/макс нарушен

**Пример ошибки:**
```
"В 1-м семестре необходимо выбрать минимум 1 курсов категории 'stem' (выбрано: 0)"
```

### Валидация всего roadmap

При валидации всего учебного плана ограничения проверяются для каждого семестра.

## API Endpoints

### Получить ограничения специализации

```bash
GET /api/v1/majors/specializations/:id/restrictions
```

### Создать ограничение

```bash
POST /api/v1/majors/specializations/:id/restrictions
Content-Type: application/json

{
  "semester": 1,
  "category": "stem",
  "min_courses": 1,
  "max_courses": 3,
  "internal_description": "Требуется хотя бы один STEM-курс"
}
```

### Обновить ограничение

```bash
PUT /api/v1/majors/restrictions/:id
Content-Type: application/json

{
  "semester": 2,
  "category": "soft",
  "min_courses": 0,
  "max_courses": 1
}
```

### Удалить ограничение

```bash
DELETE /api/v1/majors/restrictions/:id
```

## Валидация через API


```bash

  "major_id": "uuid-мейджора",
  "specialization_id": "uuid-специализации"
}
```

## Best Practices

1. **Начинайте с минимума**: Не создавайте слишком много ограничений сразу
2. **Тестируйте на реальных данных**: Проверьте ограничения на типичных учебных планах
3. **Документируйте**: Используйте `internal_description` для объяснения причин ограничений
4. **Проверяйте конфликты**: Убедитесь, что ограничения не противоречат друг другу

## Troubleshooting

### Ошибки не появляются

- Проверьте, что `specialization_id` передан в API запрос
- Убедитесь, что ограничения созданы для правильной специализации
- Проверьте, что семестр в ограничении совпадает с номером семестра

### Студент не может выбрать курсы

- Проверьте минимальные требования - возможно они слишком высокие
- Убедитесь, что в каталоге достаточно курсов нужной категории
- Проверьте доступные семестры курсов

## Миграция с newdb.md

Эта реализация упрощена по сравнению с newdb.md spec:

| newdb.md | Реализация |
|----------|-----------|
| `restrictions` + `specializationsConnections` + `disciplineGroups` | Прямое поле `Category` |
| Сложные resolver boxes | Простой подсчёт по категориям |
| Гибкие группы курсов | Фиксированные 8 категорий |

Это упрощение делает функцию проще в настройке и понимании.
